# お問い合わせフォームのスパム対策

最終更新: 2026年10月9日

## 背景

フォームからスパムが届くようになったため調査したところ、**ボット対策が一切ありませんでした**。
ハニーポット・レート制限・CAPTCHA・内容判定のいずれも無く、Server Action を叩けるものはすべて配信されていました。

## 現在の防御（実装済み・多層）

送信は次の順で検査されます。**いずれの段階でも、送信内容がログに出ることはありません**（判定理由のみ記録）。

### 1. 形式チェック（従来からあったもの）

必須項目・メール形式・文字数上限（氏名100 / メール254 / 本文5000）。

### 2. ハニーポット `website`

人間には触れない隠しフィールド。値が入っていれば自動送信と断定します。

- `display:none` ではなく**画面外配置**（最近のボットは `display:none` を避けるため）
- `tabIndex={-1}` + `aria-hidden` で、キーボード操作とスクリーンリーダーからは到達不可
- 検証済み: Tab を12回押しても到達しない

### 3. 確実にボットと判定できるパターン → 「送信成功」と表示して破棄

誤検知がほぼあり得ないものだけをここに置いています。**ボットには成功したと見せます**（失敗を伝えると手口を変えて再送するため）。

| 条件 | 理由 |
|---|---|
| ハニーポットに入力あり | 人間は触れない |
| `[url=` `[link=` `<a href` を含む | 人間はフォームにこの記法を書かない |
| URLが4つ以上 | 問い合わせの体裁ではない |
| **氏名欄に**URLが含まれる | 全項目に payload を詰めるボットの特徴 |

### 4. スコア判定 → 合計4点以上で遮断

誤検知が起こりうるものは単独では遮断せず、加点方式にしています。遮断時は**エラーを表示**します（万一の誤検知で「送れたつもり」にさせないため）。

| signal | 点 |
|---|---|
| キリル文字を含む | +3 |
| URLが2〜3個 | +2 |
| スパム語句に一致（backlink / seo service / crypto / 等） | +2〜4 |
| 日本語が一文字も無い | +2 |
| 表示から2秒未満で送信 | +1 |

**誤検知を避ける設計**: 「日本語なし」は単独では遮断しません（英語の正当な問い合わせを弾かないため）。自社URLを1つ貼る問い合わせも通ります。

### 5. レート制限

同一IPから **10分間に3件**まで。超過時は時間をおくよう案内します。

⚠️ **制約**: サーバーレスのインスタンス内メモリで保持するため、インスタンスを跨いだ分散攻撃は止められません。目的は「1つの送信元による連続投稿の抑止」と、**Resend の送信クォータ保護**です（クォータが尽きると正当な問い合わせが届かなくなるため、こちらが実害）。

## テスト

`screen()` は純粋関数なので、メールを送らずに検証できます。

```
npx tsx <テストファイル>
```

実装時に18ケース（誤検知6・スパム10・レート制限2）すべて通過を確認済みです。
**特に重要なのは誤検知テスト**で、以下が必ず通ることを確認しています。

- 通常の日本語問い合わせ
- 自社URLを1つ貼った問い合わせ
- 英語の正当な問い合わせ
- 素早く送信された正当な問い合わせ

判定ルールを変更する際は、必ずこの誤検知ケースを再確認してください。

## まだ入れていない対策：Cloudflare Turnstile（推奨）

上記はすべて**無料・外部依存なし**で実装できる範囲です。
しかし、ヘッドレスブラウザを使う本気のボットは、時間を待ってハニーポットを避ければ通過できます。

**スパムが止まらない場合は Turnstile の導入を推奨します。** 無料・ほとんどのユーザーには不可視・プライバシー配慮型（Cookie不使用）です。

導入手順:

1. Cloudflare アカウントを作成（無料）
2. Turnstile で `treeth.net` のサイトを登録し、**Site Key** と **Secret Key** を取得
3. Vercel の環境変数に追加
   ```
   NEXT_PUBLIC_TURNSTILE_SITE_KEY = <Site Key>
   TURNSTILE_SECRET_KEY           = <Secret Key>
   ```
4. フォームにウィジェットを設置し、Server Action 側で `https://challenges.cloudflare.com/turnstile/v0/siteverify` にトークンを検証させる

キーを取得いただければ実装します。**キーが無い状態で「無効時はスキップ」の分岐だけ先に入れるのは避けました** — セキュリティ経路に未検証のコードを置くことになるためです。

## 関連して実施したセキュリティ対応

### セキュリティヘッダ（`next.config.ts`）

HSTS は Vercel が付与していましたが、**それ以外は未設定**でした。

| ヘッダ | 値 |
|---|---|
| Content-Security-Policy | 下記参照 |
| X-Frame-Options | `DENY` |
| X-Content-Type-Options | `nosniff` |
| Referrer-Policy | `strict-origin-when-cross-origin` |
| Permissions-Policy | `camera=(), microphone=(), geolocation=(), interest-cohort=()` |
| X-Powered-By | 送出を停止 |

**CSP について**: `script-src` に `'unsafe-inline'` を残しています。nonce 方式の厳密な CSP はリクエストごとの nonce 生成が必要で、**全ページが静的プリレンダリングから外れます**。ユーザーアカウントもユーザー生成コンテンツも無いマーケティングサイトでは割に合わないと判断しました。

ただし CSP は無意味ではありません。script / style / font / image / connect の**読み込み元を自サイトに限定**するため、外部ホストへの参照を注入されても読み込まれません。`frame-ancestors 'none'` は `'unsafe-inline'` の影響を受けず完全に有効です。

全3ページ + 全画面スクロールで**CSP違反ゼロ**、画像6枚・フォント・Analytics すべて正常動作を確認済みです。

### 依存パッケージの脆弱性

| | 対応前 | 対応後 |
|---|---|---|
| 本番依存 | 6件（**critical 1** / high 4 / moderate 1） | **0件** |
| 開発依存のみ | — | 5件（high、lint ツール内のみ） |

**critical は Next.js 本体**（Server Components の DoS、影響範囲 ≤16.3.7）でした。本サイトは Server Components と Server Action を使っているため直接影響します。**16.2.2 → 16.4.0 へ更新**して解消しました。

残る5件は `eslint-config-next` 配下の glob 処理の DoS で、**ビルド成果物には含まれず、ローカルの lint 実行時のみ**のものです。解消には `npm audit fix --force` による破壊的変更が必要なため、リスクに見合わないと判断して据え置いています。
