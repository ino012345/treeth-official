# 2026年 UI/UX リサーチ — TREETH公式サイト改善のための根拠

調査日: 2026年9月23日
目的: TREETH公式サイト（https://www.treeth.net/）の改善判断を、流行ではなく一次情報・UX研究に基づいて行うための根拠整理。

**採用判断の基準**: 「2026年のトレンドだから」ではなく、**TREETHの事業目的（Web制作の問い合わせ獲得）にプラスかどうか**のみで判断する。

---

## 優先度A：一次情報・標準

### A-1. WCAG 2.2 / 2.3.3 Animation from Interactions

**Research finding**
W3Cは「インタラクションによって引き起こされるモーションアニメーションは無効化できなければならない（本質的な場合を除く）」と定めている。スクロールによって要素が動く（スクロールに伴う本質的な移動を除く）場合、前庭障害（vestibular disorder）を持つユーザーに吐き気・めまいを誘発しうる。OSの「視差効果を減らす」設定が `prefers-reduced-motion: reduce` として伝達される。

**TREETHへの示唆**
現行サイトはHero（400vh）とProjects（500vh）でスクロール量をcanvasフレーム再生に消費している。これは「スクロールに伴う本質的な移動」ではなく、スクロールを入力とした**演出の再生**であり、2.3.3の対象になる。実測の結果、`prefers-reduced-motion: reduce` を有効にしても挙動は一切変化しなかった（後述の監査参照）。

**判断: 採用（必須対応）**

**理由**
アクセシビリティは「あれば良い」ではなく、TREETHが「セキュリティ・品質に強い制作者」を名乗る以上、自社サイトが標準を満たしていないこと自体が信頼を損なう。かつ実装コストが低い。

---

### A-2. Core Web Vitals（web.dev / Google）

**Research finding**
2026年時点の「良好」しきい値は LCP ≤ 2.5s / INP ≤ 200ms / CLS ≤ 0.1、いずれも実ユーザー訪問の**75パーセンタイル**で評価される。2025年のWeb Almanacでは、モバイルで良好なLCPを達成しているページは62%にとどまり、LCPが最も達成困難な指標とされる。

**TREETHへの示唆**
実測では LCP 1.4s / CLS 0 と良好だった。**しかし** ページ全体のダウンロード量は**モバイルで17.70MB**（うち画像17.56MB / 227リクエスト）。LCPは「最初のフレームが速い」ため良好に見えるが、実際のユーザーはスクロールに応じて残りを延々とダウンロードし続ける。モバイル回線・従量課金のユーザーにとっては実質的な負荷であり、CWVの数値には表れない「隠れた劣化」である。

**判断: 採用（フレーム総量の削減）**

**理由**
数値がGreenでも、17MBは店舗オーナーがスマホで見る想定と噛み合わない。CWVを守りつつ総量を削る。

---

### A-3. Google Search Central / people-first content

**Research finding**
Googleは「検索順位のために作られたコンテンツ」ではなく「人のために作られたコンテンツ」を評価する。Core Web Vitalsはランキング要因の一つではあるが、**上位表示を保証するものではない**。

**TREETHへの示唆**
現行FAQに「Googleの評価（SEO）にも有利な爆速サイト」という記述があった（既に一部修正済み）。また h1 が `Ignite the Digital Core.` のみで、**ページが何のページなのかを説明していない**。これはユーザーにとっても検索エンジンにとっても情報量がゼロに近い。

**判断: 採用（h1の再設計 + SEO表現の正確化）**

**理由**
「コーポレートサイト制作」「ホームページ制作」「LP制作」は実際に見込み客が検索する語であり、かつTREETHが実際に提供しているサービスである。キーワード詰め込みではなく、事実の記述として自然に含める。

---

## 優先度B：UX研究

### B-1. Nielsen Norman Group — Scrolljacking 101

**Research finding**
NN/gのユーザビリティテストで確認された事項:
- **大多数の参加者が、少なくとも軽度の見当識喪失（disorientation）を経験した**。一部はこれを「バグ」だと解釈した。
- **目的志向のユーザーは、探索目的のユーザーより著しく忍耐力が低い**。ある参加者は「フルスワイプしたのに、どこにも進まなかった…私なら相当イラつく」と述べた。
- **テキストとスクロール速度の改変の組み合わせが最悪の結果**を生む。読みながら非標準のスクロールに対処する二重負荷がかかるため。
- **モバイルでは悪化する**。画面が小さいほど見当識喪失が強まる。
- ユーザーは閲覧時間の**80%をファーストビューより上**で費やす。

NN/gの推奨: (1)機能的価値がある場合のみ使う (2)スクロール速度を最適化 (3)**テキストを最小化** (4)**モバイルでは避ける** (5)ファーストビューより下に置く (6)ナビゲーションを「脱出口」として残す (7)通常スクロールのセクションも残す。

**TREETHへの示唆**
現行サイトは、NN/gが挙げた**悪条件をほぼすべて満たしている**:
- ファーストビューそのものがスクロール演出（推奨5に反する）
- Hero内に h1・説明文・CTA という**最重要テキストを配置**（推奨3に反する）
- モバイルでも同じ構造（推奨4に反する）
- Projectsは案件名・説明文というテキストをスクロール連動で切り替えている（推奨3に反する）
- ユーザーの主目的（サービス内容の理解・実績確認・問い合わせ）はすべて目的志向であり、最も忍耐力が低い層

**判断: 採用（Hero・Projectsのスクロール消費構造を撤廃）**

**理由**
TREETHの訪問者は「作品を鑑賞しに来た人」ではなく「制作を依頼できる相手を探している人」である。NN/gの言う「目的志向のユーザー」そのもので、最も scrolljacking に不寛容な層。ブランド表現の価値より、離脱リスクが上回る。

---

### B-2. フォームのフィールド数と完了率

**Research finding**
- NN/g: 不要なフィールドを削除すると、ほぼすべてのケースで完了率が改善する。
- フィールド数と完了率: 3項目で23.1% → 5項目で17.0% → 7項目で11.4% → 10項目以上で6.9%。**5→7項目の間に明確な崖**がある。
- Baymard Institute: 最大67%のユーザーが「入力したくない項目」「意味の分からないエラー」に遭遇した瞬間に離脱する。
- Baymard(2024, B2Bフォーム利用者500名): 必須をアスタリスクで示すより「任意」を明示するほうが、平均25%高いコンバージョン。
- B2Bでは「営業が精査する短いフォーム」が「人を怖がらせる長いフォーム」に勝る。最適は3〜4項目。

**TREETHへの示唆**
現行フォームは**お名前 / メール / お問い合わせ内容の3項目**で、既に最適解に近い。**項目を増やしてはいけない**。改善余地は項目数ではなく、**送信前の心理的不安**（何を書けばいいか分からない / 営業されそう）の側にある。

**判断: 一部採用（項目数は変更しない。不安を下げるmicrocopyのみ追加）**

**理由**
数値上すでに最良の構成。ここを触るのは改悪リスク。ただし「まだ内容が固まっていなくても大丈夫」という一文は、Baymardの言う「入力をためらう瞬間」を直接取り除く。**ただし実態として確認できない約束（返信時間など）は追加しない**。

---

### B-3. Information Scent / Progressive Disclosure / Cognitive Load

**Research finding**
ユーザーは情報の「匂い（scent）」を辿って目的地を探す。次に何があるか予測できないリンク・セクションは辿られない。Progressive Disclosureは「複雑さを段階的に開示する」手法だが、**最初の段階で全体像が掴めること**が前提。

**TREETHへの示唆**
現行Heroは `Ignite the Digital Core.` という抽象コピーのみで、「Web制作会社である」という最重要の情報の匂いがない。訪問者が「自分向けのサイトか」を判断できない。

**判断: 採用（Heroで WHO / WHAT / VALUE / CTA を即座に提示）**

---

## 優先度C：2026年デザイントレンド

### C-1. Editorial Layout（エディトリアルレイアウト）

**Research finding**
2026年の大きな潮流として、サイトを「セクションの羅列」ではなく「体験」にするエディトリアル型レイアウトが台頭。サービス業・パーソナルブランドと特に相性が良いとされる。

**TREETHへの示唆**
制作実績セクションを、スクロール連動の自動切替から**エディトリアル・グリッド**へ変えることは、トレンドとしてもUXとしても正しい方向。ユーザーが自分のペースで5件を**比較**できる。

**判断: 採用**

**理由**
トレンドだからではなく、「実績を比較したい」というユーザーの目的に、グリッドが構造的に合致するため。

---

### C-2. タイポグラフィ主導のデザイン

**Research finding**
2026年はタイポグラフィが「主要なインターフェース構造」へ昇格。大胆な見出し、レイヤー化された型処理が、ページ重量を減らす工学的要請とも合致する。

**TREETHへの示唆**
canvasフレームシーケンス（17MB）を削り、タイポグラフィ・余白・グリッドで「上質さ」を表現する方向は、**ブランド価値を落とさずに軽量化できる**数少ない解。TREETHの既存デザイン（ダーク基調・tracking-tighter・大きな余白）はすでにこの方向にある。

**判断: 採用**

---

### C-3. B2Bにおける信頼設計

**Research finding**
2026年のB2Bでは、クライアントロゴ・実績・証言・透明性のあるプライバシー表記といった**信頼のシグナル**が差別化要因になる。明確な階層とスキャン可能なコンテンツが、認知負荷を下げリード獲得に直結する。

**TREETHへの示唆**
TREETHは実クライアント5社の実績、Coconalaでの評価、有資格（情報処理安全確保支援士・応用情報技術者）という**実在の信頼材料**を持ちながら、サイト上で十分に活用できていない。特に実績は「スクロールしないと見えない」状態。

**判断: 採用（ただし数値の捏造は絶対に行わない）**

---

### C-4. Kinetic Typography / 大量のカーソルエフェクト / 実験的UI

**Research finding**
2026年トレンドとして言及されるが、NN/gの知見と衝突する領域。

**TREETHへの示唆**
Navbarのマグネティックホバーは既に実装済みで、控えめな範囲であれば「上質さ」に寄与する。ただし**操作方法を学習させるUI**（スクロールで案件が変わる等）は、目的志向ユーザーには純粋なコストになる。

**判断: 部分採用**
- マグネティックホバー・微細なホバーモーション → **維持**（Level 2モーション）
- スクロール駆動のストーリーテリング → **撤廃**
- 新規の実験的インタラクション追加 → **不採用**

**理由**
「2026年っぽさ」は動きの量ではなく、Typography / Spacing / Grid / Image treatment / Micro-interaction / Copy / Visual hierarchy で表現する方針とする。

## モーション階層の設計方針（本プロジェクトの定義）

| Level | 定義 | TREETHでの扱い |
|---|---|---|
| **Level 1** | ユーザー理解に必要な動き | 状態変化のフィードバック（FAQ開閉、フォーム送信中、hover時のアフォーダンス）。**reduced-motion時も維持**（ただし時間短縮） |
| **Level 2** | ブランド体験を高める控えめな動き | 初回表示のfade/reveal、スクロール到達時の軽い entrance、マグネティックホバー。**reduced-motion時は無効化** |
| **Level 3** | 純粋な装飾 | canvasフレームシーケンス、マーキー、装飾アニメーション。**reduced-motion時は完全停止**。かつスクロール量を消費しない形に限る |

**原則: 通常のスクロールは通常のスクロールとして機能させる。**

---

## 採用・不採用の総括

| 項目 | 判断 | 主な根拠 |
|---|---|---|
| Heroのスクロール駆動canvas（400vh） | **撤廃** | NN/g scrolljacking（目的志向ユーザーの不寛容・テキストとの併用が最悪） |
| Projectsのスクロール連動自動切替（500vh） | **撤廃** | 同上 + 比較不能 + キーボード到達不能 |
| canvasビジュアル自体 | **Heroで静的〜軽量活用** | ブランド価値を捨てない（全削除は禁止事項） |
| Editorial Portfolio Grid | **採用** | ユーザーの「比較したい」目的に構造が合致 |
| 日本語メインコピー + h1再設計 | **採用** | Information scent / people-first content |
| フォーム項目追加 | **不採用** | 3項目が最適解、増やすと完了率が落ちる |
| 不安を下げるmicrocopy | **採用** | Baymard: 67%が「ためらう瞬間」に離脱 |
| prefers-reduced-motion対応 | **採用（必須）** | WCAG 2.3.3 |
| 構造化データ（JSON-LD） | **採用** | 現状ゼロ。事実の記述のみで実装可能 |
| 数値・実績の追加 | **実在するもののみ** | 捏造は絶対禁止 |
