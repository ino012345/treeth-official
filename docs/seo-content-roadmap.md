# SEOコンテンツ ロードマップ

作成日: 2026年9月23日
状態: **設計のみ。今回のフェーズでは実装していません。**

現在のサイトは1ページ構成（トップ + プライバシー + 特商法）です。
検索とAI検索からの流入を伸ばすには、**検索意図ごとに独立したURL**が必要になります。
このドキュメントは、その追加順序と各ページの設計を定めます。

---

## 大原則

1. **架空の成果数値を書かない。** 「CV率が◯%向上」「売上◯倍」等は、実測データがあり、かつクライアントの掲載許可がある場合のみ。ない場合は成果の項目自体を省く
2. **クライアント名の掲載は事前許可を得てから。** 許可が得られない場合は「飲食店（業種のみ）」のような表記にする
3. **ページを増やすこと自体が目的ではない。** 中身の薄いページを量産すると、サイト全体の評価を下げる
4. **1ページ = 1つの検索意図。** サービスページ同士で内容が重複すると共食い（カニバリ）を起こす

---

## フェーズ1: サービスページ（優先度: 高）

トップページの「3つのサービス」は概要にとどまるため、各サービスの詳細な検索意図を受け止められていません。

| URL | 主な検索意図 | 想定キーワード |
|---|---|---|
| `/services/corporate` | 会社のホームページを作りたい | コーポレートサイト制作、会社 ホームページ 作成 |
| `/services/lp` | 集客用のLPを作りたい | LP制作、ランディングページ 制作 |
| `/services/uiux` | 既存サイトを改善したい | UI/UXデザイン、サイト 改善、リニューアル |

### 各サービスページの構成

1. **h1** — そのサービス名を含む具体的な見出し
2. **誰向けか** — 「こんな方に向いています」（対象を明示することで、合わない人の離脱を早める＝良いこと）
3. **含まれるもの** — 企画/デザイン/実装/公開のどこまでか
4. **進め方** — トップの6ステップを、このサービス固有の粒度で
5. **関連する制作実績** — フェーズ2の `/works/[slug]` へ内部リンク（2〜3件）
6. **このサービスに関するFAQ** — トップのFAQと重複させない
7. **CTA** — トップと同じ問い合わせ導線

### 注意

- 料金は、正式に確定しトップFAQと整合が取れてから記載する。現状は「個別お見積もり制」で統一
- 3ページで同じ文章を使い回さない。重複コンテンツとみなされる

## フェーズ2: 制作実績の個別ページ（優先度: 高）

現在の実績はトップページ内のカードのみで、**1件あたりの情報量が数行**しかありません。
個別ページ化することで、業種名での検索（例: 「飲食店 ホームページ 制作 事例」）に対応できます。

### URL 設計

```
/works/[slug]
```

例: `/works/torus-kikaku-corporate`, `/works/dan-chinese-restaurant`

### 各実績ページの掲載項目

| 項目 | 内容 | 必須 |
|---|---|---|
| クライアント / 業種 | 社名（許可がある場合）と業種 | ○（業種のみでも可） |
| 制作前の課題 | 依頼時に抱えていた問題 | ○ |
| 目的 | サイトで達成したかったこと | ○ |
| 情報設計 | ページ構成、導線の考え方 | ○ |
| デザイン方針 | 配色・トーンの意図と、その理由 | ○ |
| 担当範囲 | 企画/デザイン/実装/公開のどこを担当したか | ○ |
| 実装内容 | 使用技術、特筆すべき実装 | ○ |
| 公開サイト | 実際のURL（許可がある場合） | △ |
| 成果 | **実測データがある場合のみ** | △ |

### 「成果」の扱い — 最重要

- **数値を書けるのは、クライアントから実データを共有され、かつ掲載許可を得た場合のみ**
- 推測値・概算・「体感で」といった書き方も不可
- データがない場合は、この項目を丸ごと省く。無理に埋めない
- 「お客様の声」がある場合は、成果の代わりに定性的な評価として掲載できる（改変せず引用する）

### 実装メモ

- データソースは `src/lib/projects.ts` のような1ファイルに集約し、トップページのグリッドと個別ページで**同じデータを共有**する（現在の `ProjectsShowcase.tsx` 内の配列を移動）
- トップのカードから個別ページへリンクする（現在カードはリンクになっていない）
- 各ページに `CreativeWork` または `Article` の構造化データを検討。ただし**ページ上に見えている情報とだけ一致させる**

## フェーズ3: 判断材料コンテンツ（優先度: 中）

発注前に検討している層が検索する内容。問い合わせ前の不安を解消し、指名検索につなげます。

| 候補URL | 内容 |
|---|---|
| `/faq` | トップのFAQを独立ページ化し、項目を拡充 |
| `/flow` | 6ステップの詳細版。準備物・期間の目安 |
| `/about` | 経歴・保有資格・制作の考え方（E-E-A-T に寄与） |

`/about` は特に、**保有資格（情報処理安全確保支援士・応用情報技術者・個人情報保護士）という実在の裏付け**を活かせるページです。現在これらは構造化データと本文に断片的にしか現れていません。

---

## フェーズ4: 記事コンテンツ（優先度: 低 / 任意）

```
/blog/[slug]
```

着手は**フェーズ1〜3が完了してから**。

- 月1本でも継続できる場合のみ始める。更新が止まったブログは逆効果
- 「ホームページ制作 費用 相場」「WordPress以外 ホームページ」など、検討層の疑問に答えるテーマ
- 実務で実際に聞かれた質問を起点にする（＝一次情報になり、AI検索にも引用されやすい）

---

## 実装時の共通チェックリスト

新しいページを追加するときは必ず:

- [ ] `src/app/sitemap.ts` にURLを追加
- [ ] `metadata`（title / description / canonical / OGP）を設定
- [ ] h1 が1つだけで、ページ内容を説明しているか
- [ ] 既存ページと検索意図が重複していないか
- [ ] 内部リンクを張ったか（孤立ページを作らない）
- [ ] `npm run indexnow -- /新しいURL` で通知（[bing-webmaster-setup.md](./bing-webmaster-setup.md) 参照）
- [ ] Search Console の URL Inspection でインデックス登録をリクエスト
- [ ] 記載した事実に裏付けがあるか（特に数値）

## 優先順位のまとめ

```
フェーズ1  サービスページ3件      ← 検索需要が明確。最初に着手
   ↓
フェーズ2  制作実績の個別ページ    ← 業種別検索に対応。実績が資産になる
   ↓
フェーズ3  about / flow / faq     ← 信頼性の補強
   ↓
フェーズ4  ブログ（任意）          ← 継続できる場合のみ
```
